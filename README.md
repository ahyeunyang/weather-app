# 날씨 앱 프로젝트

## 프로젝트 소개

입체감 있는 SVG 캐릭터와 날씨 정보를 결합하고, 날씨에 맞는 놀거리·먹거리·볼거리 상품을 탐색해 실제 구매·예약까지 할 수 있는 모바일 커머스 앱입니다.

앱을 실행하면 움직이는 스플래시 화면이 먼저 나타나고, 화면 중앙에는 직접 만든 SVG 캐릭터가 표시됩니다. 스플래시 애니메이션이 끝나면 날씨 메인 화면으로 이동합니다.

## 기술 선택

이 프로젝트는 웹 화면을 먼저 제작한 뒤 Capacitor로 네이티브 앱과 연결하는 방식으로 개발합니다.

| 영역              | 기술                                                  |
| ----------------- | ----------------------------------------------------- |
| 프론트엔드        | React                                                 |
| 언어              | TypeScript                                            |
| 개발 및 빌드 도구 | Vite                                                  |
| 스타일            | SCSS Modules                                          |
| 캐릭터            | SVG + React/CSS 애니메이션, 현재 임시 화면은 Three.js |
| 네이티브 연결     | Capacitor                                             |
| 날씨 데이터       | 날씨 API                                              |
| 상품 및 주문      | 상품 API + 주문 데이터                                |
| 결제              | 결제 서비스 연동 예정                                 |
| Android 결과물    | APK / AAB                                             |

이 구성을 사용하면 React와 TypeScript를 연습하면서 직접 웹 퍼블리싱을 진행할 수 있습니다. 완성된 웹 결과물은 Capacitor를 통해 Android와 iOS 앱으로 패키징하고, 위치 및 알림 같은 기기 기능은 Capacitor 플러그인으로 연결합니다.

## 앱 실행 구조

```text
네이티브 기본 스플래시
  → React 웹 화면 로딩
  → SVG 캐릭터 애니메이션 인트로
  → 날씨 메인 화면
```

네이티브 스플래시는 웹 화면이 준비될 때까지 짧게 표시합니다. 현재 임시 도형은 React Three Fiber로 실행하지만, 실제 캐릭터 SVG가 준비되면 React와 CSS/SVG 애니메이션 기반으로 교체합니다.

## 첫 실행 안내

앱을 처음 실행하면 스플래시 다음에 날씨 확인, `놀러·먹으러·보러` 상품 탐색, 구매·예약과 마이페이지 기능을 4장 이내로 소개합니다. 이후 날씨 메인에서는 주요 버튼을 실제 화면 위에서 가리키는 단계형 가이드를 한 번 제공합니다. 안내는 건너뛸 수 있고 완료 여부와 가이드 버전을 기기에 저장하며, `설정 > 앱 사용 가이드`에서 언제든 다시 볼 수 있습니다. 구체적인 안내 순서와 완료 기준은 [`PAGE_ROADMAP.md`](./PAGE_ROADMAP.md)의 첫 실행 온보딩과 사용 가이드 항목에서 관리합니다.

## 쇼핑 메인 화면

`사러` 화면은 아이폰 17 기준 시안의 상대 비율을 기준으로 재구성했습니다. 기준 폭보다 작은 화면에서도 좌우 여백, 대표 비주얼, 상품 카드와 섹션 간격이 함께 축소되도록 `clamp()`, `%`와 공통 커머스 토큰을 사용합니다. 상품 이미지는 실제 에셋 연결 전까지 비율만 유지하는 빈 플레이스홀더로 표시합니다.

- 기본·서브·캡션·라인 색상은 각각 `#111`, `#999`, `#ccc`, `#ececec`이며 `_color-tokens.scss`에서 관리합니다.
- 쇼핑 화면의 기본 카드·캡션은 `0.875rem`, 보조 제목과 섹션 제목은 `1.125rem`, 상단 탭은 `1.5rem`, 날씨 질문은 `1.75rem`을 사용합니다.
- 날씨 질문은 메인 헤드라인 예외로 `1.75rem`을 사용합니다. 첫 줄은 `600` semibold, 둘째 줄은 `300` light로 구분합니다.
- 날씨 질문 아래 업데이트 시각은 `0.75rem`을 사용하며 캡션 색상 `#ccc`를 유지합니다.
- 새로고침 아래 페이지 번호는 현재 페이지 `1`을 `#111`, 전체 페이지 부분 `/3`을 캡션 색상 `#ccc`로 구분합니다.
- 상단 `사러·먹으러·놀러` 탭은 활성 상태와 관계없이 `1.5rem`을 사용합니다. 활성 탭은 `600` semibold, 비활성 탭은 `300` light로 구분합니다.
- 상품 가로 목록은 터치·트랙패드·키보드 스크롤을 지원하는 CSS 스냅 슬라이드입니다.
- 쇼핑 큐레이션 섹션 사이에는 별도의 공통 구분선을 넣지 않습니다. 대표 추천 영역 아래의 라인과 상품 목록 내부의 행 구분선만 유지합니다.
- 광고 아래 큐레이션 섹션은 서로 `2.25rem` 간격을 사용합니다. 상·하 패딩을 중복하지 않고 인접한 섹션 사이에 하나의 간격만 적용합니다.
- 큐레이션 섹션 서브타이틀에는 별도의 상단 마진을 적용하지 않습니다. 판매처 원형 표시가 있는 경우에만 표시 아래에 `0.75rem` 하단 마진을 둡니다.
- 다이어리 세로 상품 목록과 오른쪽 정렬 `214개 상품 더보기` 버튼 사이는 `1rem`입니다. 모든 상품 더보기 버튼의 오른쪽에는 `5 × 9` 비율의 `chevron-right.svg`를 사용하며 텍스트와 아이콘 사이는 `0.25rem`입니다. 화살표는 CSS 마스크로 출력해 버튼 텍스트 색상을 그대로 따릅니다.
- 광고의 `AD` 뱃지는 광고 영역의 위·오른쪽에서 공통 페이지 여백 토큰만큼 떨어진 위치에 고정합니다.
- 광고 문구는 `1.5rem` 크기와 `300` light를 기본으로 사용하고 `빙수는`만 `600` semibold로 강조합니다. 왼쪽 광고 이미지는 `public/characters/puri/puri-bingsu.svg`의 푸리 캐릭터를 `7.5rem` 정사각형 영역 안에서 원본 비율로 표시하며, 배너 하단을 기준으로 배치해 이미지가 배너 위로 돌출될 수 있습니다. 돌출 이미지의 최상단과 이전 상품 섹션 사이에는 `1.5rem` 간격을 유지합니다.
- 상단 대표 추천은 3장 가로 스냅 슬라이드입니다. 터치로 넘기거나 새로고침 모양의 다음 버튼을 누르면 이동하며 현재 위치가 `1/3` 형식으로 자동 갱신됩니다.
- 에어팟 케이스 큰 원형 상품 영역은 가운데 정렬 스냅 캐러셀입니다. 처음 진입할 때 두 번째 상품이 중앙에 보이고 양옆 상품 일부가 노출되며 좌우로 이동할 수 있습니다.
- 에어팟 케이스 큰 원형 상품 슬라이드의 상품 사이 간격은 `1.5rem`입니다. 섹션 제목과 슬라이드 사이의 상단 마진은 `1rem`입니다.
- 섹션 제목 위 원형 표시는 향후 판매처 로고가 들어갈 표시용 뱃지입니다. `이 아이들 중 하나를 데려가렴` 섹션의 원은 콘텐츠 전환 기능을 유지하지만 일반 뱃지와 동일하게 테두리와 선택 링 없이 표시합니다. 키보드 포커스일 때만 접근성용 외곽선을 표시합니다.
- `바깥은 더워서 위험하단다!` 아래 `이 아이들 중 하나를 데려가렴` 추천에는 `시원한 무날개 / 선풍기`, `힘스터 / 캡모자`, `아이눈부셔 / 선글라스`처럼 상품 종류를 둘째 줄로 내린 원형 탭을 표시합니다. 선택한 원형 아래 연결 표시가 나타나고 회색 상품 패널에는 `날개 없이 안전한 선풍기` 카드가 표시됩니다.
- 회색 탭 패널 안 사각 상품 카드 사이의 가로 간격은 `0.75rem`입니다.
- 원형 상품 탭의 이미지 영역만 `5rem` 정원으로 고정합니다. 탭 행 전체는 `1.5rem` 간격을 둔 3개의 동일 너비 열로 나누어 양쪽 끝까지 사용하며, 상품명은 각 열 너비를 사용합니다.
- 큐레이션 제목과 원형 상품 탭 사이의 상단 마진은 `1rem`입니다. 탭 아래 상품명은 `0.875rem`으로 최대 두 줄까지 표시하며, 첫 줄은 `300`, 둘째 줄의 `선풍기·캡모자·선글라스`는 `600` 굵기를 사용합니다. 두 줄을 넘으면 말줄임 처리합니다.
- 광고의 `AD` 배지는 배너 오른쪽 위에 절대 배치하고 반투명 배경과 블러를 사용합니다.
- `AD` 배지 글자는 타이포그래피 예외로 `0.625rem`을 사용합니다.
- 하단 내비게이션은 화면 아래에 고정되며 안전 영역을 포함합니다. 아래로 스크롤하면 화면 밖으로 숨고, 위로 스크롤하거나 최상단에 도달하면 다시 나타납니다.
- 하단 내비게이션의 기본 높이는 `4rem`이며, 홈 인디케이터가 있는 기기에서는 하단 안전 영역을 별도로 더합니다.

먹으러의 W 로고 마스크 크기는 커머스 토큰의 `100% auto`로 설정해 비주얼 폭을 더 크게 채웁니다.

쇼핑 화면은 `src/pages/ShoppingPage`에서 관리합니다. 모바일 기준 최대 너비는 `24.375rem`이며 작은 화면에서는 화면 너비에 맞게 줄어들고 태블릿에서는 중앙에 배치됩니다.

- 상단: 밑줄 없는 `사러`, `먹으러`, `놀러` 메뉴와 검색 플레이스홀더
- 날씨 질문: 강조 문구, 업데이트 시각, 원형 새로고침과 큐레이션 페이지 번호
- 본문: 큰 날씨 비주얼, 비주얼 오른쪽 위에 겹쳐 올라오는 대표 상품 이미지, 왼쪽 아래 상품 정보, 원형 연관 상품 4개
- 하단 콘텐츠: 이미지와 문구가 나란히 배치된 가로 광고 배너, 분류 아이콘·큐레이션 제목·세로 상품 3개·상품 더보기로 구성된 상품 섹션
- 추가 큐레이션: 날씨 준비물 3개와 상품 3열, 큰 원형 대표 상품, 단일 대표 상품, 2열 상품 그리드를 독립된 카드 순서로 배치
- 하단 고정 메뉴: 왼쪽 `쇼핑`, 가운데 `날씨`, 오른쪽 `마이페이지`

현재 상품과 프로모션 이미지는 준비 전이므로 회색 배경의 플레이스홀더로 구현했습니다. 쇼핑 화면은 제공된 `사러` 개별 화면의 정보 순서와 비율을 기준으로 구성하며 첫 진입 시 `사러`가 활성화됩니다. 현재 UI 확인 기간에는 스플래시 연결을 해제하고 앱 실행 즉시 쇼핑 화면을 표시합니다. `SplashPage` 구현 파일은 이후 진입 흐름에 다시 연결할 수 있도록 유지합니다. 실제 라우팅을 구성할 때 날씨, 쇼핑과 마이페이지 경로로 분리합니다.

상단 `사러·먹으러·놀러` 메뉴는 모두 `1.5rem`, 굵기 `650`을 사용합니다. 활성 메뉴도 같은 크기와 굵기를 유지하고 글자색만 진하게 표시합니다.

`사러` 대표 비주얼은 사용자가 제공한 `buy-sunny-w-transparent.png`를 사용합니다. 시안의 `316 × 174` 표시 영역에 대응하는 `19.75rem × 10.875rem` 크기를 적용하고 알파 투명도를 유지하며 별도 로고나 CSS 마스크를 적용하지 않습니다.

현재 `사러` 대표 영역의 큰 날씨 비주얼에는 `buy-sunny-w-transparent.png` 자체를 `316 × 174` 프레임 전체에 맞춰 표시합니다. 실제 PNG의 `298 × 174` 비율 때문에 생기던 `contain` 좌우 여백은 제거했습니다. 오른쪽 아래에는 투명 배경의 `fan-product-transparent.png`를 원본 비율을 유지하는 `contain` 방식으로 겹칩니다.

대표 W 이미지 레이어는 콘텐츠 여백을 상쇄해 페이지 오른쪽 끝에 여백 없이 맞춥니다. 대표 상품 텍스트의 좌측 여백과 다른 콘텐츠 정렬은 유지합니다.

쇼핑 화면의 현재 판매 가격은 모두 `600` semibold로 표시합니다. 취소선이 있는 회색 정가는 `400` regular를 유지합니다.

대표 상품 정보와 대표 상품 이미지는 하나의 2열 그룹으로 구성합니다. 왼쪽에는 분류·상품명·가격, 오른쪽에는 상품 이미지를 같은 행에 배치하고 이미지에만 위쪽 이동을 적용해 메인 비주얼과 겹치게 합니다. `먹으러`의 빙수도 하늘 로고 배경과 분리되어 상품 정보와 같은 그룹에 속합니다.

대표 상품의 판매가와 정가는 개별 여백을 사용하지 않고 하나의 flex 가격 행으로 묶습니다. 가격 행에 위쪽 여백과 요소 사이 간격을 적용하고 두 가격은 baseline으로 정렬합니다.

대표 상품의 텍스트 블록과 상품 컷아웃은 같은 2열 행에서 세로 가운데를 기준으로 정렬합니다. 상품 컷아웃 위아래에 자연스러운 여백을 확보하면서 두 열이 한 그룹으로 보이도록 유지합니다.

`먹으러`의 하늘 W 로고는 전체 형태를 알아볼 수 있는 크기로 콘텐츠 폭을 채운 뒤 비주얼 오른쪽에 정렬하고 오른쪽 일부가 화면 밖으로 잘리도록 구성합니다. 망고빙수와 상품 정보가 들어 있는 행 전체는 먹으러 전용 겹침 토큰으로 위쪽 비주얼을 침범하며, 컷아웃은 영역의 오른쪽 아래에 정렬합니다. 겹침은 레이아웃 여백도 함께 줄이는 음수 여백으로 처리해 섹션 아래에 불필요한 빈 공간을 남기지 않습니다.

대표 상품 행은 메인 로고 비주얼보다 높은 레이어에 배치합니다. 로고와 상품이 겹치는 영역에서는 망고빙수와 상품 정보가 항상 W 로고 위에 표시됩니다.

망고빙수는 흰 배경이 포함된 RGB 원본 대신 `public/images/shopping/eat-mango-bingsu-transparent.png` 투명 알파 PNG를 사용합니다. 이미지 래퍼의 배경과 혼합 모드에 의존하지 않아 하늘 W 로고 위에 겹쳐도 사각 배경이 나타나지 않습니다.

쇼핑 상단 탭은 `사러·먹으러·놀러` 순서를 유지하되 첫 진입 시 가운데 `먹으러`를 기본 탭으로 표시합니다. 레퍼런스의 `272 × 896` 표시 비율은 기준 모바일 화면 `390 × 1285`와 같은 비율로 보고, `24.375rem` 기준 폭과 커머스 유동 토큰으로 구성 요소의 상대 크기와 간격을 유지합니다.

쇼핑 상단의 `사러·먹으러·놀러` 탭에 적용된 `650`을 앱 전체 글자 굵기의 상한으로 사용합니다. 더 강한 텍스트도 이 값을 넘지 않으며, 공통 굵기는 `src/styles/tokens/_tokens.scss`의 `$font-weight-strong`에서 관리합니다.

전역 reset의 기본 `line-height`는 `1`로 유지합니다. 여러 줄 제목, 본문처럼 읽기 위한 행간이 필요한 텍스트는 해당 컴포넌트의 `*.module.scss`에서 용도에 맞는 `line-height`를 별도로 지정합니다.

`사러` 탭의 대표 상품은 투명 알파 배경의 `public/images/shopping/buy-orange-tshirt-transparent.png`를 사용합니다. 원본 RGB 이미지인 `buy-orange-tshirt.png`는 비교용으로만 보관하며, 상품 이미지 래퍼에도 별도 배경색을 적용하지 않습니다.

쇼핑 화면의 좌우 여백, 섹션 간격, 비주얼 높이, 대표 상품 크기와 겹침 위치, 연관 상품 간격과 광고 배너 높이는 `src/styles/tokens/_tokens.scss`의 커머스 유동 토큰으로 관리합니다. `20rem`에서 `24.375rem` 사이 모바일 너비에서는 `clamp()`와 `vw`를 사용해 비례해서 줄거나 늘어나며, 범위를 벗어나면 최소·최대값을 유지합니다.

기준 화면 폭 `24.375rem`에서 레퍼런스 비율을 환산해 좌우 여백은 약 8%, 메인 비주얼 높이는 약 51%, 대표 상품 폭은 약 41%, 광고 배너 높이는 약 26%로 설정합니다. 작은 화면에서는 같은 비율로 축소하되 읽기 어려워지지 않도록 최소값을 둡니다.

광고 배너의 `AD` 표시는 고정 회색이 아니라 배너 위에 겹치는 반투명 검정 알약형 배지로 표시합니다. 배경 투명도, 강조 오버레이, 밝은 글자 투명도와 블러 값은 `src/styles/tokens/_color-tokens.scss`와 `_tokens.scss`의 커머스 오버레이 토큰으로 공통 관리합니다.

광고 아래 이어지는 큐레이션 카드는 공통 간격 토큰을 사용합니다. 카드 구분 간격, 카드 안쪽 여백, 제목과 비주얼 사이, 비주얼과 상품 정보 사이, 카드 하단 여백을 모든 큐레이션에 동일하게 적용하며 섹션별 임의 간격은 사용하지 않습니다.

## 프론트엔드 작성 방식

앱의 기본 폰트 굵기는 `300` light입니다. 활성 탭, 주요 제목과 강조 문구처럼 별도 위계가 필요한 요소만 컴포넌트 스타일에서 semibold 또는 strong 굵기를 명시합니다.

앱 전체 기본 글꼴은 `Pretendard`를 최우선으로 사용하며, 사용할 수 없는 환경에서는 `Noto Sans KR`과 시스템 sans-serif 순서로 대체합니다.

앱의 `html`, `:root`, `body` 전역 배경은 공통 `$app-background` 토큰의 `#f7f7f7`을 사용합니다. 각 페이지의 흰색 표면은 페이지 컴포넌트에서 별도로 적용합니다.

대표 추천 아래 원형 연관 상품의 상품명과 가격은 모두 `300` light를 사용합니다. 제목 요소의 브라우저 기본 굵기가 적용되지 않도록 상품명 `h3`에도 굵기를 명시합니다.

단일 상품 섹션 제목과 상품 이미지 사이의 상단 마진은 `1rem`입니다.

광고 아래 모든 큐레이션 섹션의 상품명은 `400` regular를 사용합니다. 다이어리 세로 목록, 판매처 탭 상품, 카드 슬라이드, 큰 원형 상품, 단일 상품과 마스크 그리드에 같은 규칙을 적용합니다. 단일 상품 이미지의 원형 상품 보기 버튼은 이미지 오른쪽 중앙에 `1.875rem` 정사각형으로 배치하며 흰색 `arrow-right.svg`를 `0.625rem` 정사각형으로 표시합니다.

대표 추천 아래 원형 연관 상품 영역은 상품 사이에 `0.75rem` 간격을 두고, 좌우 여백은 `1rem`을 사용합니다. 상하 여백도 같은 전용 여백 토큰을 사용합니다.

HTML 파일에 모든 화면을 직접 작성하지 않고 React의 `.tsx` 컴포넌트로 화면을 나눠서 제작합니다. 화면의 디자인은 각 컴포넌트에 대응하는 `.module.scss` 파일에서 관리합니다.

```tsx
import styles from "./WeatherCard.module.scss";

export function WeatherCard() {
  return (
    <section className={styles.card}>
      <h2 className={styles.title}>서울</h2>
      <strong>24°C</strong>
      <p>오늘은 맑아요</p>
    </section>
  );
}
```

```scss
@use "../../styles/tokens/color-tokens" as color;
@use "../../styles/tokens/tokens" as token;

.card {
  padding: token.$space-6;
  border-radius: token.$space-6;
  background: color.$light-main;

  .title {
    font-size: token.$space-6;
  }
}
```

Vite가 React 코드를 브라우저에서 실행할 HTML, CSS, JavaScript 파일로 빌드하고, Capacitor가 이 결과물을 네이티브 앱에 포함합니다.

## SCSS 관리 원칙

- 모든 SCSS 길이 값은 `rem`을 사용하며 `px`은 사용하지 않습니다.
- `0`, `%`, `vw`, `vh`, `svh`, `dvh`, `em` 및 단위 없는 값처럼 의미상 필요한 값은 예외로 사용할 수 있습니다.
- 여백, 크기, 타이포그래피, radius 및 반응형 기준은 일반 토큰인 `src/styles/tokens/_tokens.scss`에서 관리합니다.
- 공통 색상은 컬러 토큰인 `src/styles/tokens/_color-tokens.scss`에서 관리합니다.
- 새로운 스타일은 하드코딩보다 일반 토큰과 컬러 토큰을 먼저 사용합니다.
- 초기화, 기본 폰트 및 공통 스타일은 `globals.scss`에서 관리합니다.
- UI는 컴포넌트 중심으로 제작하고, 컴포넌트 스타일은 같은 폴더의 `ComponentName.module.scss`에서 관리합니다.
- 컴포넌트의 기본 형태와 다르게 페이지에서만 필요한 배치나 변형은 각 페이지의 `PageName.module.scss`에서 관리합니다.
- SCSS 모듈을 불러올 때는 `@import` 대신 `@use`와 `@forward`를 사용합니다.
- 모바일 스타일을 기본값으로 작성하고, `48rem` 이상 태블릿 화면의 확장 스타일은 `tablet-up` mixin으로 관리합니다.
- 날씨 상태나 테마에 따라 실행 중 바뀌는 값이 필요한 경우에도 컬러 토큰을 기본값으로 사용하고 CSS 사용자 정의 속성으로 확장합니다.
- 선택자 중첩은 가급적 2~3단계 이내로 유지합니다.

브라우저 기본 스타일 초기화는 `src/styles/_reset.scss`에서 관리합니다. 모든 요소의 기본 여백과 패딩, 제목·문단·목록, 링크, 버튼과 폼 요소, 이미지·영상, 표와 fieldset의 기본 스타일을 초기화합니다. 키보드 포커스 표시는 제거하지 않으며 모션 감소 설정에서는 애니메이션과 전환 시간을 최소화합니다.

현재 스타일과 페이지 구조는 다음과 같습니다.

## 날씨 아이콘

## 퍼블리싱 우선 개발 원칙

메인 화면은 [Kakao W: Weather app](https://www.behance.net/gallery/90916115/Kakao-W-Weather-app)의 정보 배치, 캐릭터 중심 연출과 계절감만 참고합니다. 카카오 캐릭터와 원본 화면을 복제하지 않고 프로젝트의 로고, SVG 캐릭터, 날씨 아이콘과 컬러를 사용해 별도의 디자인으로 제작합니다.

날씨 메인은 큰 흰색 라운드 카드 안에 날짜와 공유·지역 추가 기능, 현재 온도와 대기질, 지역과 날씨 상태, 중앙 캐릭터 장면, 하단 상품 탐색·날씨 더보기·마이페이지 내비게이션을 배치합니다. 시간별·주간 예보의 긴 목록은 `날씨 더보기`로 연결되는 별도 예보 상세 페이지에서 제공합니다. 확정된 상세 배치와 완료 기준은 [`PAGE_ROADMAP.md`](./PAGE_ROADMAP.md)의 날씨 홈 페이지 항목에서 관리합니다.

API 연결보다 모바일·태블릿 퍼블리싱을 먼저 완성합니다. 화면에 값을 직접 고정하지 않고 실제 API 응답과 유사한 목업 데이터를 컴포넌트에 전달해, 이후 데이터 공급원만 교체할 수 있도록 구성합니다.

```ts
const mockWeather = {
  location: "마포구 창전동",
  temperature: 32,
  temperatureDiff: 5,
  minimumTemperature: 24,
  maximumTemperature: 32,
  condition: "맑음",
  fineDust: "좋음",
  ultraFineDust: "보통",
  warning: "폭염주의보",
};
```

퍼블리싱 단계에서는 다음 항목을 먼저 제작하고 검증합니다.

1. 현재 날씨, 대기질과 특보 영역
2. SVG 캐릭터 장면과 날씨별 모션
3. 시간별 및 주간 예보
4. 모바일과 태블릿 반응형 레이아웃
5. 로딩, 오류, 빈 데이터와 위치 권한 거부 상태
6. `-12°C`, `38°C`, 긴 지역명, 특보 없음과 여러 특보 같은 예외값

퍼블리싱이 완료된 뒤 Open-Meteo 날씨 및 대기질, 현재 위치, 행정동 변환과 기상특보 순서로 실제 데이터를 연결합니다. API 응답은 화면 컴포넌트에서 직접 처리하지 않고 앱 내부 날씨 데이터 형식으로 정규화하며, `weather_code`와 주야간 정보는 `WeatherIcon` 이름과 SVG 캐릭터 상태로 변환합니다.

## 개발 및 Android 빌드 흐름

### 현재 작업공간에서 실행

이 저장소는 시스템 `PATH`에 Node.js가 없어도 프로젝트 내부의 휴대용 Node.js 24.13.0을 사용할 수 있습니다. 현재 작업공간에는 `.tools/node-v24.13.0-win-x64`가 준비되어 있으며, 다음 명령으로 개발 서버를 실행합니다.

```powershell
.\dev.ps1
```

`dev.ps1`은 프로젝트 내부의 휴대용 Node.js를 우선 사용하고, 해당 런타임이 없으면 시스템에 설치된 `npm`을 사용합니다. `.tools`와 다운로드한 Node.js 압축 파일은 저장소에 커밋하지 않습니다. 새 작업공간에서는 Node.js 24를 설치한 뒤 `npm ci`를 실행하거나, 같은 버전의 Windows x64 압축 배포본을 `.tools/node-v24.13.0-win-x64`에 풀고 `npm ci`를 실행합니다.

퍼블리싱 중에는 Vite 개발 서버를 사용해 브라우저에서 빠르게 확인합니다.

```powershell
npm run dev
```

Android 앱에 반영할 때는 웹 결과물을 빌드한 후 Capacitor와 동기화합니다.

```powershell
npm run build
npm run android:sync
```

개발용 APK는 다음 명령 하나로 웹 빌드, Capacitor 동기화와 Gradle 빌드를 모두 실행해 생성합니다.

```powershell
npm run android:apk
```

생성된 APK의 기본 위치는 다음과 같습니다.

android/app/build/outputs/apk/debug/app-debug.apk

개발 단계에서는 자동 서명된 Debug APK를 휴대폰에 직접 설치해 확인합니다. 실제 배포 단계에서는 별도의 배포용 키로 서명한 APK 또는 Google Play 등록용 AAB를 생성합니다.

연결된 에뮬레이터나 휴대폰에서 바로 실행하려면 다음 명령을 사용합니다.

## 날씨 API

포트폴리오용 비상업 프로젝트의 날씨 데이터는 **Open-Meteo** 무료 API를 사용합니다.

- 비상업 용도의 무료 API는 회원가입과 API 키가 필요하지 않습니다.
- 현재 날씨, 시간별 예보 및 일별 예보를 JSON으로 받을 수 있습니다.
- Capacitor Geolocation으로 얻은 위도와 경도를 API 요청에 사용합니다.
- 무료 API는 하루 10,000회 요청 제한이 있습니다.
- Open-Meteo와 원본 데이터 출처를 앱의 정보 화면이나 하단 영역에 표기합니다.

API는 온도, 습도, 강수량, 풍속 및 `weather_code` 같은 원본 데이터만 제공합니다. 화면 디자인은 API에 종속되지 않으며 프로젝트에서 자유롭게 커스텀합니다.

| Open-Meteo 날씨 코드  | 앱에서 사용할 표현 예시                  |
| --------------------- | ---------------------------------------- |
| `0`                   | 맑음 아이콘, 맑은 배경, 맑음 캐릭터 모션 |
| `1`~`3`               | 구름 아이콘, 흐린 배경, 구름 캐릭터 모션 |
| `45`, `48`            | 안개 아이콘과 안개 효과                  |
| `51`~`67`, `80`~`82`  | 비 아이콘과 빗방울 효과                  |
| `71`~`77`, `85`, `86` | 눈 아이콘과 눈 효과                      |
| `95`, `96`, `99`      | 번개 아이콘과 천둥 효과                  |

따라서 날씨 아이콘, 한글 문구, 색상 토큰, 배경, SVG 캐릭터 표정과 애니메이션은 모두 직접 제작하고 변경할 수 있습니다. API의 `weather_code`를 앱 내부의 UI 상태로 변환하는 매핑 계층을 별도로 작성합니다.
